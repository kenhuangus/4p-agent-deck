The pattern

Seven Launches, One Design

Security controls still assume an agent that waits for a prompt.

Why a new termWhat I saw

  • Between May and October 2026, seven companies published launch material for the same agent design.
  • The security teams I work with still design controls for an agent that waits for a prompt, finishes one task and forgets what it did.
  • I think this design is the most important change in applied AI since chat assistants launched, and it needs its own threat model.

Definition

The Four Ps

Based on my research, I coined the term 4P agent for agents that combine four properties.

What is newOne agent, four properties

  • Engineers have shipped each property alone for years.
  • In 2026, product teams put all four into one agent and gave that agent a computer of its own in the cloud.
  • Each property increases the effect of the others, and in my view that amplification, not any one feature, defines the category.
Proactive
Shipped alone as notification systems that start a conversation
In combination acts without a fresh prompt
Persistent
Shipped alone as chat products that keep memory
In combination keeps that capability running 24 hours a day
Personal
Shipped alone as consumer assistants that know a household
In combination tells the agent what its user would likely want
Professional
Shipped alone as workplace copilots that read company documents
In combination gives it authority over systems colleagues and customers depend on

Starts First, Keeps Running

Each property has a literal test a buyer can apply.

TestsPass or fail

  • Persistent, running: does the agent stay on after the user closes a laptop or locks a phone?
  • Persistent, remembering: does the agent use what it stored in later weeks?

Personal · Professional

Knows One Person, Works in One Company

The same agent holds a household's data and a company's systems.

TestsPass or fail

  • Personal: two people give the same instruction and get different results, because the agent knows different things about each.
  • Professional: the agent finishes a work process, such as preparing a meeting or chasing an unpaid invoice, through the systems employees use.
  • Depending on how the maker built the product, that access places the agent inside or outside the company's controls.

Four Risks, Three Frameworks

The 4P design adds four risks that a chat assistant waiting for prompts did not have, and early Instinct users reported incidents matching three of them within weeks of launch.

Frameworks I work onHow I classify each risk

  • OWASP AIVSS, the project I lead, scores agentic AI vulnerabilities and publishes a web calculator for that scoring.
  • The OWASP Agentic Skills Top 10 (AST10) names ten risks in the skills that tell agents how to act.
  • MAESTRO is the seven-layer agentic threat model I introduced through the Cloud Security Alliance in February 2025.

Risk 1

Standing Access

An agent that checks an inbox on its own schedule cannot wait for the user to sign in.

The riskEvery account, all the time

  • Users leave mail, chat, files and often payment methods connected at all times.
  • An attacker who compromises a chat assistant gets one conversation; an attacker who compromises a 4P agent or its machine gets every connected account at once, during hours when nobody watches it.
  • Disconnecting an app stops future reads only: Forbes reports that Instinct kept Claire Vo's emails after she disconnected Gmail, and Vellum reports the team then added a deletion tool.
Credential separation: the model uses a login it never reads
In my view, this design gives security teams the most protection today. What each maker documents:
Claude DuetNever sees passwords or sign-in tokens
Meta MuseUses stored credentials without seeing them
OpenAI DotsUses saved passwords without exposing them to the model
Microsoft AutopilotCredentials scoped to the task and redacted from logs
InstinctCached credentials on the agent's own machine, per Vellum
Gemini SparkNo controls described beyond the user's choice of connected apps
PokeNot described in the reviewed material
Risk 2

Memory Poisoning

Persistent memory can make a one-time prompt injection into an instruction the agent keeps following.

The riskText from strangers becomes memory

  • Every day, a 4P agent reads mail and messages from strangers and writes notes from them into long-term memory.
  • Vellum reports that Alex Cohen emailed his own inbox a set of malicious instructions, that Instinct followed them, and that Cohen then deleted his account.
  • Removing poisoned entries is harder than recovering from one injected prompt, because nobody can easily see which remembered fact came from which sender.

Risk 3

Agent-Started Actions

In a chat product, every action starts from a prompt the user typed; with a 4P agent, the user often learns about an action from the agent's own report.

The riskThe agent chooses to act

  • Forbes reports that one Instinct user watched the agent book a restaurant table that carried a large cancellation fee.
  • Vellum reports an email that Instinct sent on Katie Jacobs Stanton's behalf without checking with her first.
  • I think approval works better per class of action, such as payments, sends, deletes and signatures, than per tool, because a tool without an approval requirement can produce the same outcome as a tool with one.
Three places makers put the check
Restrict the mode
OpenAI

While the user is away, a dot's proactive research uses read-only tools: it cannot send messages, change app content or control a browser.

Add a second agent
Meta

A separate Sentinel agent on the same Muse Secure VM, isolated at the system level, must approve anything Muse sends to the internet.

Approve named action classes
Anthropic, Google, Microsoft

Duet waits before sending, paying, signing or deleting; Spark asks before spending money or sending email; Autopilot can require sign-off for sensitive actions.

Risk 4

Delegated Authority

Every action runs under some identity, and that identity determines who can audit the action and who is accountable for a mistake.

The riskWhose name is on the action

  • Makers split into two identity models, shown on the right.
  • Here the personal and professional properties conflict: when one agent holds a family calendar and a company CRM, personal data can appear in a work message, or work data in a personal one.
  • The company's data loss controls see that message only when the agent runs inside the company's tenant; of the seven agents, Microsoft places only Autopilot inside the customer's own Microsoft 365 tenant.
The agent has its own identity
Microsoft Autopilot: one governed Entra identity per agent
OpenAI: specialist dots for organizations in preview, each with its own identity and access
Auditors can attribute each action to one agent
The agent acts as the user under terms of service
Instinct, per Vellum: appointed as the user's agent with authority to enter binding agreements and transactions
Forbes, citing TechCrunch in August 2026: the terms granted “perpetual and irrevocable” rights to store user data
The user carries the consequences
Verdict

Builder's Verdict

The makers now compete on control design more than on capability.

VerdictWhat the launch material shows

  • What changed: the largest AI labs and two startups now sell one agent design.
  • Where the design fails: every incident on slides 9 to 11 comes from Instinct, the one product with no documented approval rules, per Vellum.
  • What comes next: the makers list three directions, shown on the right.
What the makers list as next
More agents per user

OpenAI starts every user with one primary dot and envisions teams of dots working together; Google lists custom sub-agents for Spark.

More access to the user's own devices

Google lists texting and emailing Spark and control of the user's local browser as planned additions.

Stronger isolation from the maker

Meta announced a Confidential VM with keys held only by the user, for later in 2026.
